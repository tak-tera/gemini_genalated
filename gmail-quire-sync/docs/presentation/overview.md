# メールから“自分のタスク”をワンタップで Quire へ

AI（Claude）が下書きし、人が Google Chat でワンタップ承認して Quire に登録する、タスク登録の仕組み。
Google Workspace（Gmail・スプレッドシート・Apps Script・Chat）を中心に、Google Cloud プロジェクトなしで構成している。

## 1. 課題

- メールや会議で発生した作業を、手で Quire に転記している
- 転記漏れや、どのプロジェクトに入れるかの迷いが起きる
- 「予定（会議・講演の日時）」と「作業（準備・事後対応）」が混ざりやすい

## 2. 設計の考え方

| 方針 | 実装 |
|---|---|
| AI は下書きまで | Claude はスプレッドシートへの「追記」だけ。Quire への登録は人の承認後に Apps Script が行う |
| 判断の記録を残す | 候補・判定理由・承認結果をすべて「登録ログ」に1行ずつ残す |
| 使うほど賢く | 登録先の変更や Quire での移動から、送信元を振り分けルールに自動追加。Claude は判断のたびに振り分けルールと登録ログの過去の判断（最終的な登録先・却下）を参照する |
| 予定と作業を分ける | 会議・講演の日時はカレンダー、準備や事後の作業だけを Quire へ |
| 入口を増やせる | メール以外（議事録・チャット・手入力）も、共通スキルで同じ台帳に流し込む |

## 3. 構成要素（技術スタック）

| 層 | サービス | 役割 | 技術要素 |
|---|---|---|---|
| 判断 | Claude（Anthropic） | メール判定・振り分け | Claude の定期実行タスク（毎時）、Gmail／Sheets の MCP コネクタ。振り分けルールと登録ログ（過去の判断）を読んで登録先を推定 |
| 入口 | Gmail（Google Workspace） | 依頼メール | 検索条件で招待（invite.ics）・通知を除外、処理済みラベル |
| 台帳 | Google スプレッドシート（Google Workspace） | 振り分けルール・設定・登録ログ | 登録ログ A:V（候補ID、判定、ステータス、開始／終了日時、出どころ など） |
| 定期処理 | Google Apps Script（Google Workspace） | 確認カード送信・学習 | 時間主導トリガー：`processPending`（5分）、`syncQuireMoves`（毎朝） |
| 通知 | Google Chat（Google Workspace） | 確認カード | Incoming Webhook、cardsV2（ボタンは openLink） |
| 確認画面 | Apps Script Web アプリ | 登録／内容を直して登録／却下 | `doGet` ＋ `google.script.run`、実行：自分／アクセス：自分のみ |
| 出力 | Quire | タスク管理 | Quire REST API（`POST /task/id/{project}`）、OAuth 2.0（apps-script-oauth2） |

## 4. 処理の流れ

1. **毎時**：Claude が Gmail を検索し、自分の作業かを判定（予定への出席・自動通知は除外）。1通から最大3件の作業を抽出し、スプレッドシートの振り分けルールと過去の判断（同じ送信者・似た件名の最終的な登録先、却下の傾向）を参照して登録先を推定し、「承認待ち」で追記
2. **5分ごと**：Apps Script が承認待ちの行を見つけ、Chat の Webhook に確認カードを送信（1回最大20件）
3. **ワンタップ**：カードのボタンから Web アプリを開く
   - 登録する：判定どおり、期間（開始〜終了）・担当者つきで登録
   - 内容を直して登録：日程（期間／期日のみ、時刻）・登録先・優先度・担当者・メモを編集、最大5件に分割
   - 却下：登録せず記録だけ残す
4. **すぐ**：Quire API でタスクを作成し、登録ログを「登録済」に更新
5. **毎朝**：Quire で別プロジェクトへ移されたタスクを検知し、送信元を振り分けルールに追加

## 5. セキュリティ

| 対象 | 対策 |
|---|---|
| 秘密情報 | Webhook URL・OAuth トークン・署名鍵はスクリプト プロパティのみ。コード・シート・リポジトリに置かない |
| ボタンのリンク | Web アプリは本人のみアクセス可。さらに操作ごとに HMAC-SHA256 署名を付け、改ざん・偽リンクを拒否 |
| 入力 | 登録先は振り分けルールにあるものだけ。日付・時刻・担当者・文字数・件数をサーバー側で検証 |
| 二重登録 | LockService で排他制御し、処理済みの行は再登録しない |
| 外部由来の文字列 | HTML エスケープと長さ制限。リンクは Google・Quire の許可ドメインのみ |
| プロンプトインジェクション | メール本文はデータとして扱い、指示には従わない。AI の書き込みは追記に限定 |

## 6. 運用のポイント

- 振り分けルールの「送信元」「関係性メモ」を少しずつ育てると、General（未分類）行きが減る
- Apps Script を直したら、Web アプリのデプロイを「新バージョン」で更新する（URL は変わらない）
- 日時は日本時間で扱い、Quire API には UTC で渡す

## 7. ひとこと

AI は下書きまで。決めるのは人。判断の記録が台帳に残り、使うほど振り分けが賢くなる。
