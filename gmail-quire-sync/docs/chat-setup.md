# Chat 版（トラック1）のセットアップ

TC スペースの投稿を Workspace Studio で判定し、タスクらしいものを Quire の登録候補にします。
確認カードは元のメッセージのスレッドに返り、寺尾さん・投稿者・担当者案の人（t-consulting.biz の人だけ）が操作できます。

```
TC スペースの投稿 ─▶ Studio（Gemini：Chat 用スキル）─▶ Webhook ─▶ 受付口 ─▶ 登録ログ（承認待ち）
                                                                         │ 5分ごと
                      TC スペースの元のスレッドに確認カード ◀── 本体の Apps Script
                                  │ ボタン
                                  ▼
                       承認ページ（t-consulting.biz 内）─▶ Quire（担当者案／担当者なし）
```

所要時間は 30〜40 分ほどです。上から順に進めてください。

---

## 1. スプレッドシート

登録ログの AA〜AC 列の見出し（担当者／スペース／スレッド）は追加済みです。作業はありません。

## 2. TC スペースに Webhook を作る

1. Google Chat で TC スペースを開き、スペース名の横の「▼」→「アプリと統合」→「Webhook を追加」
2. 名前の例: `Quire 登録確認`
3. 表示された URL（`https://chat.googleapis.com/v1/spaces/…`）を控える。チャットやドキュメントには貼らない

## 3. 本体の Apps Script を更新する

### 3-1. コードを置き換える

`apps-script/` の次のファイルを、エディタで丸ごと置き換えます（同じ名前のファイルに貼り付け）。

| ファイル | 変わったところ |
|---|---|
| `Config.gs` | AA〜AC 列、バージョン表示 |
| `Webhook.gs` | スペースへの返信、操作できる人の確認 |
| `WebApp.gs` | 承認ページで操作できる人を確認、担当者の初期値 |
| `Quire.gs` | 担当者案で登録、担当者を指定できないときは担当者なしで作り直す |
| `Cards.gs` | カードに担当者案を表示 |
| `Jobs.gs` | チャット由来のカードを元のスレッドへ |
| `Setup.gs` | 設定チェックの項目追加 |
| `appsscript.json` | 開いた人のアドレスを知るための権限、組織内への公開 |

`Sheet.gs` と `Structure.gs` は変更ありません。

### 3-2. スペースの Webhook を登録する

「プロジェクトの設定」→「スクリプト プロパティ」に追加します。

| プロパティ | 値 |
|---|---|
| `SPACE_WEBHOOK_TC` | 手順 2 の URL |

プロパティ名の `TC` の部分は、Studio から届く「スペース」の値と同じにします（手順 6 の試験で、登録ログの AB 列に入った値を確かめてください）。
AB 列が `spaces/AAAA…` の形なら、`SPACE_WEBHOOK_AAAA…`（spaces/ の後ろ）でも登録できます。
一致するものが無いときは、カードは今の確認用スペースに届きます（止まりはしません）。

### 3-3. 権限を承認する

エディタで関数 `checkSetup` を実行します。新しい権限（メールアドレスの表示）の承認画面が出たら許可してください。
ログで次の行が `OK` になっていることを確かめます。

- `チャットのスペースの Webhook: TC`
- `登録ログの列: AA〜AC`
- `Web アプリの持ち主: terao.takeshi@t-consulting.biz`

### 3-4. 承認ページを組織内に公開する

「デプロイ」→「デプロイを管理」→ 鉛筆アイコン

- バージョン: **新しいバージョン**
- アクセスできるユーザー: **t-consulting.biz 内の全員**（実行するユーザーは「自分」のまま）

「デプロイ」を押します。URL は変わりません（`WEBAPP_URL` はそのまま）。

メール由来の候補は、これまでどおり寺尾さんしか操作できません。
チャット由来の候補は、寺尾さん・投稿者・担当者案の人が操作でき、それ以外の人や組織外の人には「操作できません」と表示されます。

## 4. 受付口（Studio の Webhook 先）を更新する

1. 受付口のプロジェクトで `Intake.gs` を最新の `apps-script-intake/Intake.gs` に置き換える
2. 関数 `setupIntakeToken` を実行して合言葉を作り直す（以前のスクリーンショットに写った分の対応も兼ねる）
3. 「デプロイを管理」→ 鉛筆 →「新しいバージョン」→「デプロイ」（URL は変わりません）
4. Studio の**メールのフロー**の Webhook URL の `?key=` 以降を、新しい合言葉に差し替える

## 5. Studio を設定する

### 5-1. スキル「Quire タスク判定（Chat）」を作る

Studio の「スキル」で新しいスキルを作り、`docs/studio-chat-skill.md` の「スキルの本文」を貼り付けます。
`【スプレッドシート】` の位置にスプレッドシート「Gmail→Quire 振り分けルール」をチップで入れ、メンバー表の内容を確認してください。

### 5-2. フローを作る

| ステップ | 設定 |
|---|---|
| 開始条件 | 「チャット メッセージを受信したとき」／会話の種類別／スペースと名前付きグループ DM／スペース: TC／絞り込みなし |
| ステップ2 | 「Gemini に相談」。プロンプトは `docs/studio-chat-skill.md` の「ステップ2のプロンプト」 |
| ステップ3 | 「Webhook の送信」。URL は受付口の URL ＋ `?key=`（手順 4 の新しい合言葉）、メソッド POST、ペイロードは下のとおり |

ペイロード（`@（…）` は開始条件の変数のチップ。無い変数の行は消す）:

```
@（ステップ2: Gemini で作成されたコンテンツ）
source: チャット
message_id: @（メッセージ ID または メッセージ名）
chat_url: @（メッセージへのリンク）
thread: @（スレッド名）
sender: @（送信者のメールアドレス）
space: @（スペース名）
text: @（メッセージ本文）
received_at: @（メッセージの日時）
```

- `source: チャット` は必ず入れる（メールと区別するため）
- `message_id` が無いと、同じ投稿の二重登録を防げません。変数の一覧に無い場合は教えてください
- `thread` があると、カードが元のメッセージへの返信として届きます。無ければスペースに新しく投稿されます

## 6. 試す

1. TC スペースに、例えば「西川さん、来週金曜までに見積書のドラフトをお願いします」と投稿する
2. Studio の実行結果で、Webhook のレスポンスが `{"ok":true,"added":1}` になることを確かめる
3. 登録ログの最後の行を確かめる
   - V 列「チャット」、AA 列に担当者案、AB 列にスペース、AC 列にスレッド
   - AB 列の値と、手順 3-2 のプロパティ名が合っているか
4. 5分以内に、元のメッセージのスレッドに確認カードが返ることを確かめる
5. もう1名のメンバーにボタンを押してもらい、操作できること・Quire に担当者つきで登録されることを確かめる
6. 雑談や「了解です」のような投稿では候補ができない（`"added":0`）ことも確かめる

## 7. 運用中に見ること

- Studio の実行回数と Gemini の利用量（全投稿で動くため）
- 受付口の「実行数」（Apps Script の画面）
- 登録ログで、チャット由来の候補の却下の割合と、担当者案の当たり外れ

Claude 版（メールの定期実行）は一時停止のままです。メールは Studio のメールのフローで受け付けています。
