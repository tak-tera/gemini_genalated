# Google Workspace Studio から使う（Gemini 版の入口）

Claude の定期実行タスクの代わりに（または並行して）、Google Workspace Studio のフローでメールを判定し、
Webhook で候補を送る方法です。確認カード、Quire への登録、学習は今の仕組みをそのまま使います。

```
Gmail 受信 ─▶ Studio：Gemini でタスク判定 ─▶ Webhook（POST）
                                              │
                                              ▼
                            受付口（Apps Script、別プロジェクト）… 合言葉を確認し「登録ログ」に「承認待ち」で追記
                                              │
                                              ▼ ここから先は今の仕組みと同じ
                            確認カード（Chat）→ 登録する／直して登録／却下 → Quire
```

## なぜ受付口を別に作るのか

今の Apps Script の Web アプリ（承認ページ）は「アクセスできるユーザー: 自分のみ」で公開しています。
Studio の Webhook は Google のログイン情報を付けずに送るため、承認ページの URL には届きません。
承認ページを「全員」に開くのは避けたいので、候補を追記するだけの小さな受付口を別のプロジェクトとして作り、
こちらだけを「全員」で公開します。受付口は合言葉（INTAKE_TOKEN）が合わないリクエストを無視し、
登録ログへの追記以外は何もしません（Quire の鍵も持ちません）。

## 設定手順

1. https://script.google.com/ で新しいプロジェクトを作る（名前の例: `Quire 受付口（Studio）`）
2. `apps-script-intake/Intake.gs` と `appsscript.json` を貼り付ける（マニフェストの表示は「プロジェクトの設定」でオン）
3. スクリプト プロパティに `SPREADSHEET_ID`（今と同じスプレッドシート）を入れる
4. 関数 `setupIntakeToken` を実行し、ログに出た合言葉を控える（チャットやドキュメントには貼らない）
5. 関数 `testIntake` を実行する。5分以内にテストのカードが Chat に届けば OK（カードは却下する）
6. 「デプロイ」→「新しいデプロイ」→ ウェブアプリ。実行: 自分、アクセスできるユーザー: **全員**
   - 管理コンソールで匿名アクセスの Web アプリが制限されていると「全員」を選べません。その場合は管理者設定を確認する
7. 出てきた URL の末尾に `?key=（合言葉）` を付けたものが、Studio の「Webhook または API URL」になる
8. 下の初期プロンプトで Studio のフローを作る

## Webhook ステップの設定（Studio の画面）

| 欄 | 入れるもの |
|---|---|
| Webhook または API URL | `受付口の URL?key=合言葉` |
| メソッド | POST |
| ペイロード | 下のとおり。`@` で変数を入れる |

ペイロード（1行目は Gemini ステップの出力の変数。2行目以降は Gmail のきっかけの変数）:

```
@（ステップ2: Gemini で作成されたコンテンツ）
message_id: @（ステップ1: メール ID）
gmail_url: https://mail.google.com/mail/?authuser=（自分のアドレス）#all/@（ステップ1: メール ID）
sender: @（ステップ1: 送信者 メールアドレス）
subject: @（ステップ1: メールの件名）
received_at: @（ステップ1: メールの日時）
```

- メールのリンクの変数は無いため、メール ID から組み立てる。`authuser=` を付けると、複数アカウントでログインしていても正しいアカウントで開く
- スレッド ID ではなくメール ID を使う。スレッド ID だと、同じスレッドに後から届いた新しい依頼が「処理済み」とみなされて飛ばされる

- Content-Type の設定欄はありませんが、受付口は本文をそのまま読むので問題ありません
- 2行目以降は、Gmail のきっかけにその変数があるものだけで構いません。無い行は消してください
- `message_id` に Gmail のメッセージ ID が入ると、Claude 版と同じ ID になり、両方を動かしても二重登録になりません
- Gemini の出力を `"…"` で囲んだり、JSON の中に入れたりしないでください（引用符が崩れて読めなくなります）

## 試すときの注意

- **Studio の画面で決まること**：Webhook の本文や Content-Type を設定できるか、メールの ID やリンクを変数として渡せるか、
  条件分岐のステップがあるかは、Studio の画面で確認してください。受付口はどの場合にも対応しています。
  - 本文が JSON でなく、Gemini の文章の中に JSON が入っているだけでも読み取ります
  - 合言葉は URL の `?key=` でも、本文の `"token"` でも受け付けます
  - 条件分岐が無ければ毎回送ってかまいません（`"is_task": false` は受付口が無視します）
  - メールの ID が無いときは、送信者・件名・受信日時から ID を作り、同じメールの二重登録を防ぎます
- **Claude 版との重複**：Claude の定期実行と同時に動かすと、同じメールが2件の候補になることがあります
  （Studio からメール ID が渡せない場合）。試す間は Claude の定期実行タスクを止めるか、対象を絞ってください。
- **Gemini 版でできないこと**：Studio の Gemini は登録ログの過去の判断や Quire のスナップショットを読まないため、
  セクションと依存関係の提案はしません（確認カードの「内容を直して登録」で選べます）。
  送信元が振り分けルールに一致すれば、受付口がルールどおりに振り分けます。人が登録先を直した結果は今と同じく
  振り分けルールに学習されるので、使うほどルールで決まる割合が増えます。
- **返り値**：受付口は `{"ok": true, "added": 件数}` を返します。合言葉が違うと `{"ok": false, "error": "unauthorized"}`。
