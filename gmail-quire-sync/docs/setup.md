# 設定手順（Webhook 方式・Google Cloud 不要）

所要時間は 15〜20 分ほどです。上から順に進めてください。
画面の名前は変わることがあるので、見つからないときは近い名前の項目を探してください。

## 0. 用意するもの

- Google Workspace アカウント（t-consulting.biz）
- Quire アカウント
- スプレッドシート「Gmail→Quire 振り分けルール」の ID
  （URL の `https://docs.google.com/spreadsheets/d/【ここ】/edit` の部分）

---

## 1. Webhook が使えるか確認する（管理者）

1. 管理コンソール（https://admin.google.com/）→「アプリ」→「Google Workspace」→「Google Chat」→「Chat アプリの設定」。
2. 「受信 Webhook を許可する」（Allow incoming webhooks）が **オン** になっていることを確認します。

## 2. 通知用のスペースを作り、Webhook を発行する

1. Google Chat で「＋ 新しいチャット」→「スペースを作成」。名前の例: `Quire登録確認`。
   メンバーは自分だけにします。
2. スペース名の横の「▼」→「アプリと統合」（Apps & integrations）→「Webhook を追加」（Add webhooks）。
   - 名前: `Quire登録確認`
   - アバターの URL: 空欄でかまいません
3. 「保存」すると表示される URL（`https://chat.googleapis.com/v1/spaces/…` で始まる長い URL）をコピーします。

> この URL を知っている人は誰でもこのスペースに投稿できます。
> 保存先は手順 5 のスクリプト プロパティだけにして、チャット・メール・ドキュメント・リポジトリには貼らないでください。

## 3. Apps Script プロジェクトを作る

1. https://script.google.com/ →「新しいプロジェクト」。名前の例: `Gmail→Quire 登録確認`
2. 左の歯車「プロジェクトの設定」で「`appsscript.json` マニフェスト ファイルをエディタで表示する」に **チェック**。
3. 同じ画面で **スクリプト ID** を控えます（手順 6 で使います）。
4. エディタに戻り、`apps-script/` フォルダのファイルをすべて作成して中身を貼り付けます。
   - `appsscript.json` は既存のものを丸ごと置き換え
   - `.gs` ファイルは「＋」→「スクリプト」で同じ名前（拡張子なし）で作成
     （`Config` / `Sheet` / `Quire` / `Webhook` / `Cards` / `WebApp` / `Jobs` / `Setup`）
   - 最初からある `コード.gs` は削除してかまいません
5. 保存します。マニフェストに書いてある OAuth2 ライブラリは自動で読み込まれます。

> `clasp`（コマンドラインツール）を使う場合は、`apps-script/` フォルダで `clasp create` / `clasp push` でも同じ状態になります。

## 4. Web アプリとして公開する（ボタンのリンク先）

カードのボタンを押すと開くページです。自分しか開けない設定で公開します。

1. 「デプロイ」→「新しいデプロイ」→ 種類の選択（歯車）で「**ウェブアプリ**」。
   - 説明: `ボタンのリンク先`
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **自分のみ**
2. 「デプロイ」を押します。初回は Google の承認画面が出るので許可します。
3. 表示される **ウェブアプリの URL**（`https://script.google.com/macros/s/…/exec`）をコピーします。

> コードを直したあとは「デプロイを管理」→ 鉛筆アイコン → バージョン「新しいバージョン」で更新します。
> こうすると URL は変わりません。「新しいデプロイ」を作ると URL が変わるので注意してください。

## 5. スクリプト プロパティを設定する

「プロジェクトの設定」→ 下の方の「スクリプト プロパティ」→「スクリプト プロパティを追加」。

| プロパティ | 値 |
|---|---|
| `SPREADSHEET_ID` | スプレッドシートの ID |
| `CHAT_WEBHOOK_URL` | 手順 2-3 の Webhook の URL |
| `WEBAPP_URL` | 手順 4-3 のウェブアプリの URL（`/exec` で終わるもの） |
| `QUIRE_CLIENT_ID` | 手順 6 で取得 |
| `QUIRE_CLIENT_SECRET` | 手順 6 で取得 |

`LINK_SECRET`（ボタンのリンクに付ける署名の鍵）と、Quire の接続情報は自動で追加されます。手で変更しないでください。

## 6. Quire のアプリを登録して接続する

1. https://quire.io/apps/dev を開き、「Create new app」。
   - App name: `Gmail→Quire 登録確認`（任意）
   - Choose the Quire organization: T-Consulting
   - **Redirect URL**: `https://script.google.com/macros/d/【スクリプトID】/usercallback`
     （【スクリプトID】は手順 3-3 の値。手順 4 のウェブアプリの URL とは別物です）
   - Permission: タスクの読み取り・書き込み（Read/Write tasks）を許可
2. 作成後に表示される **Client ID** と **Client Secret** を、手順 5 のスクリプト プロパティに入れます。
3. Apps Script のエディタで、関数 `showQuireAuthUrl` を選んで「実行」。
4. 「実行ログ」に出た URL をブラウザで開き、Quire で **Allow** を押します。
   「接続が完了しました」と出れば OK です。
5. 関数 `testQuire` を実行し、ログに自分の名前が出ることを確認します。

## 7. 動作確認とトリガー登録

1. 関数 `checkSetup` を実行し、ログがすべて `OK` になっていることを確認します。
2. 関数 `sendTestMessage` を実行し、手順 2 のスペースにテストメッセージが届くことを確認します。
3. 関数 `installTriggers` を実行します（5分ごとの確認と、毎朝の学習が動き始めます）。

### カードの試し方

「登録ログ」タブの2行目に、手でテスト行を入れます。

| 列 | 値の例 |
|---|---|
| B: Gmail メッセージID | `test-001` |
| C: 送信者 | `テスト <test@example.com>` |
| D: 件名 | `テスト依頼` |
| E: タスク名案 | `テストタスクを確認する` |
| G: 判定プロジェクト | `TC Work` |
| K: ステータス | `承認待ち` |

5分以内にスペースへカードが届きます。

- 「登録する」→ ブラウザが開き「登録しました」と出れば成功です
- 「登録先を変える」→ プルダウンでプロジェクトを選んで登録します
- 「却下」→ 登録せずに記録だけ残します

テストタスクは Quire で削除してください。

## 8. Claude の定期実行タスクを作る

メールを読んで「承認待ち」を書き込む部分です。`docs/claude-routine.md` の指示文で、
Claude Code の定期実行タスク（1時間ごと）を作ります。Claude に「定期実行タスクを作って」と頼めば設定します。
Gmail と Google Sheets のコネクタが必要です。

## うまくいかないとき

| 症状 | 見るところ |
|---|---|
| カードが届かない | `checkSetup` の結果と、Apps Script の「実行数」画面のエラー。`Chat Webhook エラー 403` なら手順 1 の管理者設定 |
| ボタンを押すと「ファイルを開けません」 | ブラウザで複数の Google アカウントにログインしていると起きます。t-consulting.biz だけでログインしたブラウザ（またはシークレット ウィンドウ）で開く |
| ボタンを押すと「アクセス権がありません」 | 手順 4 の「アクセスできるユーザー: 自分のみ」と、ブラウザのログイン中アカウントが同じか |
| コードを直したのに動きが変わらない | 手順 4 の注意どおり、デプロイを「新しいバージョン」に更新する |
| `Quire に未接続です` | `showQuireAuthUrl` をもう一度実行。Quire の接続は6か月使わないと切れます |
| Quire 登録が `404` | 振り分けルールの「プロジェクトID」が Quire の URL（`/w/` の後ろ）と一致しているか |

## セキュリティ

この仕組みで守っていることと、運用で気をつけることです。

### 仕組みで守っていること

| 対象 | 対策 |
|---|---|
| Webhook URL・Quire の鍵 | スクリプト プロパティにだけ保存。コード・シート・リポジトリには書かない。ログにも出さない |
| 送信先 | `chat.googleapis.com` 以外の URL には送らない |
| ボタンのリンク | Web アプリは「自分のみ」アクセス可。さらにリンクごとに署名を付け、署名が合わないリンク（偽物や書き換えたもの）では何もしない |
| 登録先 | 振り分けルールにある有効なプロジェクトにしか登録しない |
| 二重登録 | 処理済みの行は何度ボタンを押しても再登録しない |
| メール由来の文字列 | カード・Web ページでは HTML として解釈されないようにエスケープし、長さも制限。リンクは `mail.google.com` と `quire.io` のものだけ使う |
| 大量の書き込み | 5分ごとの処理は最大 20 件まで |
| メールの悪用（なりすまし指示） | Claude はメール本文の指示に従わず、送信・削除はしない。付けるのは処理済みラベルだけ。最終的な登録は必ずあなたがボタンで判断する |

### 運用で気をつけること

- **スプレッドシートと Apps Script を他人と共有しない。** 編集できる人はスクリプト プロパティ（Webhook URL や Quire の鍵）を見られます。
- **通知用スペースのメンバーは自分だけにする。** カードには件名や送信者が表示されます。
- **Quire のアプリは Private のまま** にし、権限はタスクの読み書きだけにします。
- **漏れたかもしれないとき:**
  - Webhook URL → スペースの「アプリと統合」で Webhook を削除して作り直し、新しい URL をプロパティに入れる
  - Quire → https://quire.io/apps でこのアプリの接続を解除し、`resetQuireAuth` → `showQuireAuthUrl` で接続し直す。必要なら Quire の開発者画面で Client Secret を再発行する
  - ボタンのリンク → 関数 `rotateLinkSecret` を実行（送信済みカードのボタンはすべて無効になります）
- **使わなくなったら** トリガーを削除し（Apps Script の「トリガー」画面）、Webhook と Quire のアプリ接続も解除します。

## 設定を変えたいとき

- **確認なしで自動登録したい**: 設定タブの「Google Chat で確認する」を `FALSE` にする
- **General の入れ先を変えたい**: 設定タブで振り分けルールのプロジェクト名を指定する
- **Quire の担当者を変えたい**: 設定タブの「Quire の担当者」を変える（`me` は自分。複数は `;` 区切りでメールアドレス。空欄なら担当者なし）
- **プロジェクトを増やしたい**: 振り分けルールに1行追加（有効にチェック、プロジェクトID は Quire の URL から）
