# 設定手順

所要時間は 40〜60 分ほどです。上から順に進めてください。
画面の名前は変わることがあるので、見つからないときは近い名前の項目を探してください。

## 0. 用意するもの

- Google Workspace アカウント（t-consulting.biz）
- Quire アカウント
- スプレッドシート「Gmail→Quire 振り分けルール」の ID
  （URL の `https://docs.google.com/spreadsheets/d/【ここ】/edit` の部分）

---

## 1. Google Cloud プロジェクトを作る

1. https://console.cloud.google.com/ を開き、上部のプロジェクト選択から「新しいプロジェクト」を作成します。
   名前の例: `gmail-quire-sync`
2. 作成したプロジェクトを選んだ状態で、「API とサービス」→「ライブラリ」から次の2つを **有効** にします。
   - **Google Chat API**
   - **IAM Service Account Credentials API**
3. 「API とサービス」→「OAuth 同意画面」（または「Google Auth Platform」）を開き、
   ユーザーの種類を **内部** にして、アプリ名とサポートメールだけ入力して保存します。
4. 「IAM と管理」→「設定」で **プロジェクト番号**（数字）を控えます。手順 3 で使います。

## 2. サービスアカウントを作る（Chat にカードを送るため）

ボタン付きカードを「アプリとして」送るには、サービスアカウントが必要です。鍵ファイルは作りません。

1. 「IAM と管理」→「サービス アカウント」→「サービス アカウントを作成」。
   名前の例: `quire-chat-bot`。ロールの付与は不要なので、そのまま「完了」します。
2. 作成したサービスアカウントのメールアドレス（`quire-chat-bot@…iam.gserviceaccount.com`）を控えます。
3. そのサービスアカウントを開き、「アクセス権を持つプリンシパル」（または「権限」）タブ →「アクセスを許可」。
   - 新しいプリンシパル: **自分のメールアドレス**
   - ロール: **サービス アカウント トークン作成者**（Service Account Token Creator）

> 組織のポリシーでこの操作ができない場合は、サービスアカウントの鍵（JSON）を作り、
> 中身をスクリプト プロパティ `SERVICE_ACCOUNT_KEY` に貼る方法でも動きます。
> 鍵は流出すると悪用されるため、なりすまし方式（上の手順）をおすすめします。

## 3. Apps Script プロジェクトを作る

1. https://script.google.com/ →「新しいプロジェクト」。名前の例: `Gmail→Quire 登録確認`
2. 左の歯車「プロジェクトの設定」で次の2つを行います。
   - 「`appsscript.json` マニフェスト ファイルをエディタで表示する」に **チェック**
   - 「Google Cloud Platform（GCP）プロジェクト」→「プロジェクトを変更」→ 手順 1-4 の **プロジェクト番号** を入力
3. 同じ画面で **スクリプト ID** を控えます。手順 5 で使います。
4. エディタに戻り、`apps-script/` フォルダのファイルをすべて作成して中身を貼り付けます。
   - `appsscript.json` は既存のものを丸ごと置き換え
   - `.gs` ファイルは「＋」→「スクリプト」で同じ名前（拡張子なし）で作成
     （`Config` / `Sheet` / `Quire` / `ChatApi` / `Cards` / `ChatEvents` / `Jobs` / `Setup`）
   - 最初からある `コード.gs` は削除してかまいません
5. 保存します。マニフェストに書いてある OAuth2 ライブラリは自動で読み込まれます。

> `clasp`（コマンドラインツール）を使う場合は、`apps-script/` フォルダで `clasp create` / `clasp push` でも同じ状態になります。

## 4. スクリプト プロパティを設定する

「プロジェクトの設定」→ 下の方の「スクリプト プロパティ」→「スクリプト プロパティを追加」。

| プロパティ | 値 |
|---|---|
| `SPREADSHEET_ID` | スプレッドシートの ID |
| `SERVICE_ACCOUNT_EMAIL` | 手順 2-2 のサービスアカウントのメール |
| `OWNER_EMAIL` | 自分のメールアドレス（ボタン操作をこの人だけに限定します） |
| `QUIRE_CLIENT_ID` | 手順 5 で取得 |
| `QUIRE_CLIENT_SECRET` | 手順 5 で取得 |

`CHAT_SPACE`（チャットの送信先）は手順 7 で自動的に入ります。

## 5. Quire のアプリを登録して接続する

1. https://quire.io/apps/dev を開き、「Create new app」。
   - App name: `Gmail→Quire 登録確認`（任意）
   - Choose the Quire organization: T-Consulting
   - **Redirect URL**: `https://script.google.com/macros/d/【スクリプトID】/usercallback`
     （【スクリプトID】は手順 3-3 の値）
   - Permission: タスクの読み取り・書き込み（Read/Write tasks）を許可
2. 作成後に表示される **Client ID** と **Client Secret** を、手順 4 のスクリプト プロパティに入れます。
3. Apps Script のエディタで、関数 `showQuireAuthUrl` を選んで「実行」。
   初回は Google の承認画面が出るので許可します。
4. 「実行ログ」に出た URL をブラウザで開き、Quire で **Allow** を押します。
   「接続が完了しました」と出れば OK です。
5. 関数 `testQuire` を実行し、ログに自分の名前が出ることを確認します。

## 6. Chat アプリを設定する

1. Apps Script で「デプロイ」→「デプロイをテスト」（Test deployments）を開き、
   **Head デプロイ ID** をコピーします。
   （「新しいデプロイ」→ 種類「アドオン」で作ったデプロイの ID でもかまいません）
2. Google Cloud コンソールで「Google Chat API」→「構成」（Configuration）タブを開き、次のように入力します。
   - アプリ名: `Quire登録確認`
   - アバターの URL: `https://www.gstatic.com/images/branding/product/2x/chat_48dp.png`
   - 説明: `メールから作ったタスクの登録確認`
   - インタラクティブ機能: **有効**
   - 機能: 「1:1 のメッセージを受信する」に **チェック**（スペースへの参加は不要）
   - 接続設定: **Apps Script** を選び、手順 6-1 のデプロイ ID を貼る
   - 公開設定: 「このアプリを特定のユーザーと…に公開する」で **自分のメールアドレスだけ**
3. 保存します。

> 構成画面に「この Chat アプリを Google Workspace アドオンとして作成する」というチェックがあれば、
> **チェックしたまま** にしてください（`appsscript.json` はこの形式に合わせてあります）。
> チェックを外す（従来形式）場合は、`appsscript.json` の `"addOns": {…}` を `"chat": {}` に置き換えてください。
> コードはどちらの形式のイベントでも動きます。

## 7. チャットを開いて送信先を登録する

1. Google Chat を開き、「＋ チャットを開始」→「アプリを検索」で `Quire登録確認` を探して開きます。
2. 何かメッセージ（例: `状態`）を送ります。「承認待ちは 0 件です」と返事が来れば、
   この1対1チャットが送信先として保存されます。

## 8. 動作確認とトリガー登録

1. 関数 `checkSetup` を実行し、ログがすべて `OK` になっていることを確認します。
2. 関数 `sendTestMessage` を実行し、チャットにテストメッセージが届くことを確認します。
3. 関数 `installTriggers` を実行します（5分ごとの確認と、毎朝の学習が動き始めます）。

### カードの試し方

「登録ログ」タブの2行目に、手でテスト行を入れます。

| 列 | 値の例 |
|---|---|
| B: Gmail メッセージID | `test-001` |
| C: 送信者 | `テスト <test@example.com>` |
| D: 件名 | `テスト依頼` |
| E: タスク名案 | `テストタスクを確認する` |
| G: 判定プロジェクト | `TC Work` |
| K: ステータス | `承認待ち` |

5分以内にチャットへカードが届きます。「登録する」を押して Quire にタスクができれば完成です
（テストタスクは Quire で削除してください）。

## 9. Claude の定期実行タスクを作る

メールを読んで「承認待ち」を書き込む部分です。`docs/claude-routine.md` の指示文で、
Claude Code の定期実行タスク（1時間ごと）を作ります。Claude に「定期実行タスクを作って」と頼めば設定します。
Gmail と Google Sheets のコネクタが必要です。

---

## うまくいかないとき

| 症状 | 見るところ |
|---|---|
| カードが届かない | `checkSetup` の結果。`CHAT_SPACE` が「なし」なら手順 7 をやり直す |
| `サービスアカウントのトークン取得に失敗（403）` | 手順 2-3 のロール付与と、IAM Service Account Credentials API の有効化 |
| `Chat API エラー 403/404` | 手順 6 の構成（デプロイ ID、公開設定）と、手順 3-2 の GCP プロジェクト番号 |
| ボタンを押すとエラー | Apps Script の「実行数」画面でエラー内容を確認 |
| `Quire に未接続です` | `showQuireAuthUrl` をもう一度実行。Quire の接続は6か月使わないと切れます |
| Quire 登録が `404` | 振り分けルールの「プロジェクトID」が Quire の URL（`/w/` の後ろ）と一致しているか |

## 設定を変えたいとき

- **確認なしで自動登録したい**: 設定タブの「Google Chat で確認する」を `FALSE` にする
- **General の入れ先を変えたい**: 設定タブで振り分けルールのプロジェクト名を指定する
- **プロジェクトを増やしたい**: 振り分けルールに1行追加（有効にチェック、プロジェクトID は Quire の URL から）
