# モデルの選び方

2026-11 時点の調査結果と、それを踏まえた設定です。
モデルの提供状況や料金は変わりやすいので、半年に一度くらい AI Studio のモデル一覧と料金ページで見直してください。

## 結論

| 設定 | モデル | 理由 |
|---|---|---|
| 音声のモデル | `gemini-4-argon` | バッチ対応。1回に約8.4時間の音声を扱え、話し方の注記などの細かい指示にも従う |
| 動画のモデル | `gemini-4-argon` | 映像も読めるので、画面共有の資料を書き起こせる。長い動画の理解力も高い |
| 予備のモデル | `gemini-3.1-pro` | Argon が使えないとき（提供状況の変化、名前の変更など）に自動で切り替える |

`gemini-3.5-transcribe` は今回の仕組みには合わないため、使いません（理由は下記）。

## 3つのモデルの比較

| | gemini-4-argon | gemini-3.1-pro | gemini-3.5-transcribe |
|---|---|---|---|
| 種類 | 汎用の最新モデル | 汎用の1つ前の Pro | 文字起こし専用 |
| 入力 | 音声・動画・画像・文字 | 音声・動画・画像・文字 | **音声だけ** |
| 1回に扱える音声 | 約8.4時間 | 約8.4時間 | **1時間**（話者分けや時刻を付けると **30分**） |
| 指示文 | 自由に書ける | 自由に書ける | **書けない**（設定項目だけ） |
| バッチ（約半額） | 対応 | 対応 | **非対応** |
| 話者分け | 指示文で行う | 指示文で行う | 機能として対応（8人まで。3人以上は試験的） |
| 料金（100万トークンあたり・通常） | 入力 $4 / 出力 $20（2026-11-30 までは $2 / $10） | 入力 $2 / 出力 $12（20万トークン超は $4 / $18） | 入力 $2 / 出力 $12 |
| 注意点 | 無料枠なし（有料枠前提なので問題なし）。コンテキストキャッシュ非対応 | プレビュー版の可能性がある（提供終了が早いことがある） | 新しいモデルで、提供条件がまだ動いている |

料金はサードパーティのまとめも含みます。正確な値は AI Studio の料金ページで確認してください。

## Transcribe を使わない理由

この仕組みでは、後で Claude が「空気感・トーン」「キラーフレーズ」「認識のズレ」「合意の確度」「語られていないこと」まで整理します。
そのため文字起こしの段階で、発言だけでなく次のことも書き残させています。

- 〔沈黙 約5秒〕〔語気が強まる〕〔歯切れが悪い〕など、話し方や場の様子
- 録画の場合は、画面共有されたスライドの見出しや数値
- 区間をまたいで同じ人をそろえるための、話者の特徴メモ

Transcribe は指示文を受け付けないため、これらを書かせることができません。動画（画面）も読めません。
また1回30分（話者分けあり）の制限とバッチ非対応のため、2時間の会議では区切る回数が増え、料金も割引になりません。
発言の文字起こしそのものの精度は高いと考えられますが、今回の目的では Argon の方が合っています。

## 仕組みの側での対応

モデルの選び方に合わせて、Apps Script を次のように直しました。

1. **音声と動画でモデルを分けて設定できる**（設定タブ「音声のモデル」「動画のモデル」）。
   今はどちらも Argon ですが、例えば音声だけ安いモデルにする、といった切り替えが設定だけでできます。
2. **予備のモデルへ自動で切り替える**。選んだモデルが「見つからない」「対応していない」で失敗したら、
   予備のモデルでもう一度試し、処理ログの X列（使用モデル）と U列（メモ）に記録します。
3. **長さの見積もりを新しいモデルに合わせた**。Gemini 3 以降は音声を1秒25トークンで数えます（以前は32）。
   以前の値のままだと長さを短く見積もり、録音の最後を取りこぼすため、短めに見積もらない値に直しました。
4. **思考レベルを「低」にする**。文字起こしに深い推論は不要なので、思考に使われる分の料金を抑えます。
5. **1区間の最大出力を 32,768 トークンにした**。Apps Script からの直接呼び出し（ストリーミングなし）の上限に合わせました。
   30分の会議の書き起こしなら十分に収まります。
6. **30分ずつの区切りは続ける**。動画は1回あたり「音声付きで約45分まで」とする資料もあるため、
   30分に区切っておけば、どの資料の上限にもかかりません。出力の途中切れも防げます。
7. `checkSetup` で、設定した各モデルの名前が正しいか・バッチに対応しているかを確かめられるようにしました。

## 料金の目安（2時間の録音、バッチ方式）

音声は、区間ごとに録音全体を Gemini に渡し、指定した時間帯だけを書き起こさせています（2時間なら約18万トークン × 4区間）。

- gemini-4-argon: 約 $2（300円前後）。2026-11-30 までの導入価格ならその半分程度
- gemini-3.1-pro: 約 $1（150円前後）

## Transcribe モード（音声のモデルを Transcribe にした場合）

音声のモデルに `gemini-3.5-transcribe` を指定すると、次の「2段階」で文字起こしします（mp3 のみ）。

1. mp3 を25分ずつ（設定「Transcribe の区切り（分）」）ファイルとして切り出す。
   Transcribe は時間帯の指示が効かず、話者分けありだと1回30分までのため。mp3 は短いフレームの連続なので、フレームの区切りで切れば再生・認識できる
2. 切り出した音声を Transcribe に送り、発言を書き起こす（話者分けあり。バッチ非対応なので通常方式で1区間ずつ）
3. 同じ音声を「様子メモのモデル」（既定 `gemini-4-argon`）に送り、話者の特徴と、話し方・場の様子のメモだけを作らせる
4. 2 と 3 を1つの文字起こし文書にまとめ、Claude が突き合わせて整理する

- mp3 以外（m4a、wav、動画など）は切り出せないため、様子メモのモデルで従来どおり文字起こしします
- Transcribe は Interactions API（`POST /v1beta/interactions`）で、`transcription_config.mode` に `{"type":"verbatim","diarization_mode":"speaker"}` を指定して呼びます（Audio transcription ガイドの形）。
  言語は `ja-JP` を指定します（設定「Transcribe の言語」。空欄なら自動判定）
- 発言ごとの時刻は既定で付けません（単語ごとの時刻を付けると精度が落ちることがあるため）。設定「Transcribe の時刻」をオンにすると付きます
- `testTranscribe` を実行すると、録音の先頭約3分で呼び出しを事前に確かめられます
- Transcribe が使えない（モデルが見つからない等）ときは、様子メモのモデルによる従来の文字起こしに自動で切り替えます
- 料金の目安（2時間）: Transcribe と Argon のどちらにも25分ずつの音声だけを送るため、従来の方式（毎回録音全体を送る）より入力が少なくなります。
  一方、バッチの割引はききません

## 今後の選択肢（必要になったら）

- **料金を下げたい**: 音声のモデルを `gemini-3.1-pro` にする（動画は Argon のまま）。設定タブを変えるだけです。
- **発言の聞き取り精度をさらに上げたい**: Transcribe で発言を正確に書き起こし、Argon にはそれと音声を渡して
  話し方の注記と話者名を付けさせる「2段階」にできます。ただしモデル呼び出しが倍になり、仕組みも複雑になるので、
  まずは Argon だけで精度を見てから判断するのがよいと考えます。
- **長い動画を安くしたい**: Argon には、動画の必要な部分だけを読む処理モード（agentic video understanding）があります。
  画面共有の多い会議で料金が気になる場合に検討できます。
