# 設定手順

所要時間は 20〜30 分ほどです。上から順に進めてください。
作るものの名前はすべて接頭語 `mtgmin` で始めます（一覧は `docs/naming.md`）。
画面の名前は変わることがあるので、見つからないときは近い名前の項目を探してください。

## 0. 用意するもの

- Google Workspace アカウント（t-consulting.biz）
- 空のスプレッドシート（名前: `mtgmin-管理シート`）。URL の `https://docs.google.com/spreadsheets/d/【ここ】/edit` が ID
- 監視するフォルダと、追記先の Google ドキュメント（フォルダごとに1つ）

---

## 1. Gemini API キーを用意する（有料枠）

1. https://aistudio.google.com/ を開き、Workspace アカウントでログインします。
2. 「Get API key」（API キーを取得）→「API キーを作成」。プロジェクトは新規作成にし、次の名前にします。
   - プロジェクト名: `mtgmin-gemini`
   - プロジェクト ID: `mtgmin-gemini-tc`（ID は世界で一意なので、使われていたら `mtgmin-gemini-tc2` のように末尾を変える）
   - API キーの名前: `mtgmin-gas-key`（名前を付けられる画面なら）
3. 同じ画面でそのプロジェクトの「請求先を設定」（Set up billing）を行い、**有料枠（Paid tier）** にします。
   - 無料枠のままだと、送った内容が Google の製品改善に使われることがあります。必ず有料枠にしてください。
   - 料金の目安（バッチ方式・Gemini 4 Argon）: 2時間の録音で 200〜300 円程度。モデルや料金改定で変わるので、AI Studio の料金ページで確認してください。
   - 使いすぎに気づけるよう、Google Cloud の「お支払い」→「予算とアラート」で予算 `mtgmin-budget`（例: 月 3,000 円）を作っておくと安心です。
4. 表示された API キーをコピーします。

> API キーを知っている人は誰でもあなたの請求で Gemini を使えます。
> 保存先は手順 3 のスクリプト プロパティだけにして、チャット・メール・ドキュメント・リポジトリには貼らないでください。

## 2. Apps Script プロジェクトを作る

1. スプレッドシートを開き、「拡張機能」→「Apps Script」。名前: `mtgmin-gas`
   （https://script.google.com/ から単独で作ってもかまいません）
2. 左の歯車「プロジェクトの設定」で「`appsscript.json` マニフェスト ファイルをエディタで表示する」に **チェック**。
3. エディタに戻り、`apps-script/` フォルダのファイルをすべて作成して中身を貼り付けます。
   - `appsscript.json` は既存のものを丸ごと置き換え（Google Docs API の拡張サービスが自動で有効になります）
   - `.gs` ファイルは「＋」→「スクリプト」で同じ名前（拡張子なし）で作成
     （`Config` / `Sheet` / `Drive` / `Gemini` / `Transcribe` / `Prompt` / `DocsWriter` / `Jobs` / `Setup`）
   - 最初からある `コード.gs` は削除してかまいません
4. 保存します。

## 3. スクリプト プロパティを設定する

「プロジェクトの設定」→ 下の方の「スクリプト プロパティ」→「スクリプト プロパティを追加」で2つ登録します。

| プロパティ | 値 |
|---|---|
| `SPREADSHEET_ID` | 手順 0 のスプレッドシートの ID |
| `GEMINI_API_KEY` | 手順 1 の API キー |

## 4. タブを作り、監視フォルダを登録する

1. エディタ上部の関数の選択で `setupSheets` を選び「実行」。初回は権限の確認が出るので許可します
   （スプレッドシート、ドライブ、ドキュメント、外部サービスへの接続、トリガー）。
2. スプレッドシートに「監視フォルダ」「設定」「処理ログ」「整理結果」タブができ、
   ドライブのマイドライブに `mtgmin-文字起こし（作業用）` フォルダが作られます。
3. 「監視フォルダ」タブに、フォルダごとに1行ずつ入れます。

   | 列 | 内容 |
   |---|---|
   | A 有効 | チェックを入れると監視する |
   | B フォルダ名 | 自分用のメモ（例: `A社 定例`） |
   | C 監視フォルダ | フォルダの URL か ID |
   | D 追記先ドキュメント | 議事録を追記する Google ドキュメントの URL か ID |
   | E メモ文書 | 会議メモが別のドキュメントにあるときだけ入れる。空欄なら D をメモとして読む |

   2行目以降にチェックボックスを付けるには、A列を選んで「挿入」→「チェックボックス」。

4. 「設定」タブを確認します。主な項目:
   - **音声のモデル / 動画のモデル**: 既定はどちらも `gemini-4-argon`
   - **予備のモデル**: 既定は `gemini-3.1-pro`。上のモデルが使えないとき自動で切り替えます。
     モデル名は AI Studio のモデル一覧の表記に合わせてください（`checkSetup` で名前が正しいか確かめられます）
   - **Transcribe の区切り（分）/ 様子メモのモデル**: 音声のモデルを `gemini-3.5-transcribe` にしたときだけ使います（`docs/models.md` 参照）。
     使う場合は、手順 6 で `testTranscribe` を実行して呼び出しが通るか確かめてください
   - **思考レベル**: 既定は「低」（文字起こしに深い推論は不要なため、料金を抑える）
   - 選び方の理由は `docs/models.md` を参照
   - **処理方式**: `バッチ`（約半額・結果は通常数分〜数時間）か `通常`（すぐ実行）
   - **監視開始日時**: これより後に作られたファイルだけを処理します（既存のファイルをまとめて処理しないため）。
     過去のファイルも処理したいときは日付を前にずらします
   - **文字起こしの保持日数**: 追記後、文字起こしを残す日数（既定 7 日。0 なら追記後すぐ削除）

## 5. 議事録フォーマットを用意する

1. 新しい Google ドキュメント「mtgmin-議事録フォーマット」を作り、`docs/format.md` の `---` より下を貼り付けます。
   （貼り付けた原稿は Step 3 の途中で切れています。元のスキルの続きを追記してください）
2. そのドキュメントの URL を、「設定」タブの「議事録フォーマット文書」に入れます。

## 6. 動作確認とトリガー登録

1. `checkSetup` を実行し、「表示」→「ログ」（または実行ログ）で、すべて `OK` になっているか確認します。
2. `testAppendFormat` を実行すると、監視フォルダ1行目の追記先ドキュメントの末尾に書式のサンプルが入ります。
   見出し・箇条書き・チェックボックス・太字を確認したら、サンプル部分は手で消してください。
3. `installTriggers` を実行します（処理: 10分ごと / 文字起こしの削除: 毎日3時台）。
4. 短い録音（数分）を監視フォルダに置き、「処理ログ」に行が増えてステータスが「整理待ち」まで進むか確かめます。
   ファイルを置いてから最初の検出まで、10〜20分ほどかかります（同期中のファイルを避けるため）。

## 7. Claude の定期実行タスクを作る

`docs/claude-routine.md` の指示文で、Claude Code の定期実行タスク `mtgmin-整理と追記` を作ります。

- 実行間隔: 1〜2時間ごと（急ぎでなければ1日数回でもよい）
- コネクタ: Google Drive、Google Sheets、Google Calendar
- リポジトリは不要です

「整理待ち」の行が「追記待ち」になり、10分以内に「追記済」になってドキュメントに議事録が入れば完了です。

## clasp でコードを送る（任意）

Apps Script エディタへの手での貼り付けの代わりに、clasp でリポジトリの内容をそのまま送れます。

1. https://script.google.com/home/usersettings で「Google Apps Script API」をオンにする
2. 自分の PC で `npm install -g @google/clasp` → `clasp login`。ホームフォルダに `.clasprc.json` ができる
3. Claude Code のクラウド環境の設定で、環境変数 `CLASPRC_JSON` に `.clasprc.json` の中身を登録する（チャットには貼らない）
4. スクリプト ID は `apps-script/.clasp.json` に書いてある（プロジェクトを作り直したら書き換える）
5. `meeting-minutes/scripts/clasp-push.sh` を実行すると送られる（`status` を付けると送るファイルの一覧だけ表示）

- 送るとエディタ上の中身は上書きされる。修正はリポジトリ側で行う
- スクリプト プロパティとトリガーは変わらない
- このログイン情報があれば、自分のすべての Apps Script プロジェクトを書き換えられる。不要になったら Google アカウントの「サードパーティのアクセス」から clasp の許可を取り消す

## うまくいかないとき

| 症状 | 確認すること |
|---|---|
| 処理ログに行が増えない | 監視フォルダの A列がオンか / ファイルの作成日時が「監視開始日時」より後か / 置いてから10分以上たったか |
| 「対象外」になった | 2GB（設定の上限）を超えています。音声だけを取り出すか分割してください |
| 「エラー」になった | U列（メモ）の内容を確認し、原因を直したら `retryErrors` を実行。追記で失敗した行は追記から、文字起こし済みの行は整理から、それ以外はアップロードからやり直します |
| 「文字起こし中」のまま進まない | バッチ方式は最長24時間かかることがあります。急ぐときは設定の処理方式を「通常」にして、Q列（バッチ名）を空にし M列を「Gemini準備中」に戻します |
| 話者名が違う・聞き間違いが多い | 録音環境の影響が大きいです。マイクを話者に近づける、オンライン会議は音声を直接録る、などが効きます |
| 画面共有の資料が読めていない | 設定の「動画の画質」を「標準」に（1時間を超える録画では、区切りを20分程度に短くしてください） |

## 運用のヒント

- **Google Meet の会議**なら、Meet の「Gemini によるメモ作成」や文字起こしを使う方が手軽です。
- **ボイスレコーダーの設定**をモノラル・低ビットレートにすると、アップロードが速くなります（精度はほぼ変わりません）。
- ファイル名に日時が入っていると（例: `20261021_1400.m4a`、`2026-10-21 14-00.webm`）、開催日時の判定が確実になります。
- 元の録音・録画ファイルは移動も削除もしません。不要になったら手で整理してください。

## 設定を変えたいとき

- フォーマットを変える → 「mtgmin-議事録フォーマット」ドキュメントを直す（次回の整理から反映）
- 監視フォルダを増やす → 「監視フォルダ」タブに1行追加
- モデル・区切り・画質・保持日数 → 「設定」タブ
- 文字起こしの指示を変える → `apps-script/Prompt.gs`
