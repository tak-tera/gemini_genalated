# 議事録フォーマット（Google ドキュメントに貼る原稿）

この内容を Google ドキュメント「議事録フォーマット」に貼り付け、その URL をスプレッドシートの「設定」タブ
「議事録フォーマット文書」に入れてください。Claude は毎回このドキュメントを読んで整理します。
フォーマットを変えたいときは、このドキュメントを直すだけで次回から反映されます。

> 自動処理では、次の2点だけ読み替えます（Claude の指示文側で指定済み）。
> - 「コードブロックで囲む」は不要（行ごとにスプレッドシートへ書き、Apps Script が見出し・箇条書き・チェックボックスに整えて追記する）
> - 会議メモは、監視フォルダごとに決めた「メモ文書」（空欄なら追記先ドキュメント）から読む

---

## Formatting & Style Rules

- **コードブロック出力の徹底**:
  - 原則として余計な前置きや後書きは省き、````markdown` から始まり ```` で終わるコードブロックで囲んで出力する。
  - コードブロック内の見出しや箇条書きの前後には**空行を入れず**、すべての行を詰めて記述する（Googleドキュメント貼り付け時の空行混入防止のため）。
- **引用・出典タグの禁止**:
  - `[cite]` や `[x]` などの引用タグ・出典番号は絶対に記述しない。
- **トーンの使い分け**:
  - 整理ドキュメント本文: 洗練された「だ・である調」または「体言止め」
  - ユーザーへの補足が必要な場合: 丁寧な「です・ます調」
- **日付フォーマット**:
  - 文章の途中を除き、日付は必ず `YYYY-MM-DD` 形式をデフォルトとして使用する（例: `2026-10-21`）。
- **見出し階層**:
  - 最上位は `#`（見出し1）から開始する。
  - **見出し1 (`#`)**: `# YYYY-MM-DD HH:MM-HH:MM 【会議タイトル】` （時間が不明または日のみの場合は `# YYYY-MM-DD 【会議タイトル】` とし、常に同一フォーマットを維持する）
  - **見出し2 (`##`)**: 大項目セクション
  - **見出し3 (`###`)**: 議題・トピック単位
- **ToDo（アクションアイテム）の記述形式**:
  - Googleドキュメントへ貼り付けた際にチェックボックスまたは箇条書きとして扱いやすいよう、`- [ ] [誰が]：[何をするか]（期限：YYYY-MM-DD）` の形式で記述する。
  - 担当者や期限が未定の場合は `（担当未定）` `（期限未定）` と明記する。

## Workflow Steps

### Step 1: 日付照合による対象スコープの特定
1. 提供された「音声・録画・文字起こしデータ（ファイル名・日時情報）」と「会議メモ（複数日分が蓄積されている可能性あり）」の両方の日付・時刻・タイトルを照合する。
2. メモの中から「今回の音声データに対応する日付のセクション」を正確に切り出す。（※メモが提出されず音声データのみの場合は、音声データ全体からアジェンダと議論を抽出する）
3. 出席者情報（所属企業・機関ごとに分類）を特定する。

### Step 2: メモ箇所の重点深掘りと9つの観点によるディテール抽出
ユーザーがメモした箇所を中心に音声・文字起こしを深く掘り下げ、以下の9つの観点を織り込んで整理する。

1. **【メモ記載事項・前提・キャプチャ情報】**: メモに書かれた前提、数値、画面共有・キャプチャの内容。
2. **【きっかけ・トリガー】**: 誰のどの発言やどのデータを機にその議論が始まったか・風向きが変わったか。
3. **【各参加者の立場・背景・思い】**: 発言の字面だけでなく、背後の事情、守りたい条件、本音。
4. **【参加者の様子・空気感・トーン】**: 危機感、苦渋のトーン、熱量、歯切れの悪さ、沈黙、安堵、場の緊張や緩和。
5. **【具体例・比喩・生きた発言（キラーフレーズ）】**: 会議内で出た象徴的な言葉や比喩表現（「『……』と表現された」などカギ括弧でそのまま残す）。
6. **【認識のズレ・前提の食い違い】**: 議論が噛み合わなかった場合の、言葉の定義やスコープのすれ違い構造。
7. **【合意・非合意の境界線と発言の確度】**: 誰が何に同意・非同意か。また、その発言のコミットメント温度感（確定なのか、持ち帰りなのか、個人の推測なのか）。
8. **【語られていないこと・未消化の論点】**: 本来議論すべきだが誰も切り出さなかった点、暗黙にスルーされた課題、時間切れで浮いた論点。
9. **【ユーザー自身の主観メモ・着眼点】**: メモに記されたユーザー自身の疑問・違和感・仮説を他者の発言と区別して明記。

### Step 3: 出力テンプレートに沿った生成（空行なし・引用タグなし・コードブロック囲み）
余計な挨拶やメタな説明は省き、以下の通り**単一のMarkdownコードブロック内に行間を詰めて（空行なしで）、かつ引用元タグを一切含めずに**直接出力する。

```
# YYYY-MM-DD HH:MM-HH:MM 【会議タイトル】
## 1. 開催概要・出席者
- **開催日時**: YYYY-MM-DD HH:MM - HH:MM
- **出席者**（敬称略・順不同）:
  - [所属機関・企業名A]：[氏名1]、[氏名2]
  - [所属機関・企業名B]：[氏名3]、[氏名4]
## 2. 決定事項（合意内容と背景・条件）
- **[決定事項の件名]**: [合意された具体的内容]
  - **背景・経緯**: [なぜその決定に至ったか、誰のどのような意見が反映されたか]
  - **付帯条件・留保事項**: [合意にあたって添えられた条件や注意点]
## 3. 議論および発言の詳細整理
### (1) [トピック名（ユーザーの手書きメモ項目を最優先で立てる）]
- **前提・メモ記載事項**:
  - [手書きメモの情報、数値、キャプチャ・図表の内容などを漏らさず記述]
- **議論の展開・各参加者の発言と様子（★メモ箇所は特に重点深掘り）**:
  - [きっかけ、誰がどのような立場・思い・トーンで発言し、どうやり取りが展開したか、生きた発言や比喩、認識のズレなどを「だ・である調」で要約せず詳細に記述]
- **合意・非合意の状況と確度**:
  - [誰が何に賛同し、誰が難色を示したか、発言の確度（確定／持ち帰り／個人見解）]
- **未言及・空白の論点 / メ
【※ ここから先は貼り付けが途中で切れています。元のスキルの続き（第3節の残りと、ToDo などの後続セクション）をここに追記してください】
```
