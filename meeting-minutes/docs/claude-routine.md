# Claude の定期実行タスク（文字起こしの整理と追記）

Claude Code の定期実行タスクとして、1〜2時間ごとに動かします（急ぎでなければ1日数回でもかまいません）。
必要なコネクタ: **Google Drive**、**Google Sheets**、**Google Calendar**（会議名・出席者の照合に使う。無くても動く）。
Google Docs への書き込みは Apps Script が行うので、Claude からドキュメントは直接書き換えません。

`【スプレッドシートID】` を実際の ID に置き換えて使ってください。

## Claude が触る範囲

| 場所 | 読む／書く |
|---|---|
| 「設定」タブ | 読む（議事録フォーマット文書の URL） |
| 「処理ログ」タブ | 読む。書くのは **M列（ステータス）・S列（会議見出し）・U列（メモ）・Y列（メモの見出し）だけ** |
| 「整理結果」タブ | 整理結果を1行ずつ追加する |
| 文字起こし文書・メモ文書・フォーマット文書 | 読むだけ |

---

## 指示文

```
あなたの仕事は、会議の録音・録画の文字起こしを読み、決められたフォーマットで議事録に整理して、
Google スプレッドシートの「整理結果」タブに書き込むことです。
Google ドキュメントへの追記は別の仕組み（Apps Script）が行うので、あなたはドキュメントを書き換えないでください。
コードの変更やコミットも不要です。

スプレッドシート ID: 【スプレッドシートID】

## 手順

1. 「設定」タブ（'設定'!A:B）を読み、「議事録フォーマット文書」の URL からドキュメント ID を取り出して、
   Google Drive の read_file_content で全文を読む。これが整理のフォーマットとルールです。
2. 「処理ログ」タブ（'処理ログ'!A:Y）を読み、M列（ステータス）が「整理待ち」の行を上から最大2件選ぶ。
   無ければ何もせず終了する。列の意味:
   A 検出日時 / B ファイルID / C ファイル名 / D 監視フォルダ / E 追記先ドキュメントID / F メモ文書ID /
   G 種類 / J ファイル作成日時 / K 録音日時(ファイル名から推定) / L 長さ(分) / R 文字起こし文書ID（カンマ区切り、区間順）
3. 1件ずつ次を行う。
   a. R列の文字起こし文書を、区間の順にすべて read_file_content で読む。
      各文書の先頭に区間と時刻の範囲、「■話者メモ」、「■本文」がある。
      区間の先頭約30秒は前の区間と重なっているので、つなぐときに重複を除く。
      区間ごとに「話者A」などの呼び名が違うことがあるので、話者メモの特徴・役割・呼びかけを手がかりに同一人物をそろえる。
      〔 〕内は話し方・場の様子・画面の内容の注記なので、空気感やトーン、画面共有の内容として整理に生かす。
      音声のモデルが Transcribe の場合、文書は「■文字起こし」（Transcribe による発言の書き起こし）と
      「■話者メモ」「■様子メモ」（別モデルによる話し方・場の様子のメモ）に分かれている。
      ■文字起こしの時刻は区間の先頭からの時刻、■様子メモの時刻は元ファイル先頭からの時刻なので、
      区間の開始時刻を足して突き合わせる。■文字起こしの「話者1」などの番号は区間ごとに振り直されることがあるので、
      話者メモと様子メモを手がかりに実名・同一人物をそろえる。発言内容は ■文字起こし を正とする。
   b. 会議メモを読む。F列が空でなければ F列の文書、空なら E列（追記先ドキュメント）を read_file_content で読む。
      複数日分のメモが蓄積されている場合は、録音日時に対応するセクションだけを使う（フォーマットの Step 1）。
      セクションは「## 2026年11月2日 | 会議名」のような日付と会議名の見出しで始まることが多い。
      日付が同じで、会議名・時間帯・内容が録音と合うものを対応するセクションとする（同じ日に複数あれば最も合うもの）。
      対応するメモが無ければ、文字起こしだけで整理する。
      文書が長くて一度に読めない場合は、録音日の前後の部分だけを探して読む。
   b2. 差し込み位置を決める。E列（追記先ドキュメント）に、対応するセクションの見出しがあるかを確かめる。
      - ある場合: その見出しの文字を、ドキュメントに表示されているとおりに控える（例: 「2026年11月2日 | MWU 次年度予算打ち合わせ」。
        「## 」などの記号やリンクの URL は含めない）。整理結果はそのセクションの終わり（次の日付見出しの直前）に差し込まれる。
        整理結果の先頭に日付見出しは付けない（セクションの見出しがすでにあるため）。
      - 無い場合: 整理結果はドキュメントの先頭（タイトルの直後）に差し込まれる。
        整理結果の1行目に、追記先ドキュメントの既存のセクション見出しと同じ形・同じ階層の日付見出しを付ける
        （例: 既存が「## 2026年10月28日 | 会議名」なら「## 2026年6月9日 | MWU 部課長会後の勉強会」）。
   c. 開催日時と会議名を決める。手がかりの優先順: メモの見出し → Google カレンダーの予定 → K列 → J列。
      Google カレンダーは、録音日時の前後（時刻が分からなければその日一日）の予定を検索し、
      時間帯と内容が合う予定があれば、そのタイトル・開始終了時刻・出席者を参考にする。
      終了時刻は開始時刻＋L列の長さを目安にする。分からない部分は推測で埋めず、フォーマットの「時間が不明」の形にする。
   d. 追記先ドキュメント（E列）に、これから書く議事録の見出し（フォーマットの最初の見出し。例: 「… 2026-06-09_summary」）がすでにあれば、二重に書かない。
      その場合は整理結果を書かずに M列を「追記済」、U列に「同じ見出しがすでにあるため追記しませんでした」と書いて次へ進む。
   e. フォーマット文書のルールと出力テンプレートに従って整理する。ただし次の点は読み替える。
      - コードブロック（```）で囲まない。「```markdown」や「```」の行は書かない。
      - 1行 = 1段落。空行は入れない。見出しは「# 」「## 」「### 」、箇条書きは「- 」、
        1段下げるときは行頭に半角スペース2つ、ToDo は「- [ ] 」、太字は「**…**」で書く（この記法だけが書式に変換される）。
      - 出典番号や引用タグは書かない。
      - 文字起こしにない内容を作らない。聞き取り不確かな語は、確かめようがなければ断定しない。
   f. 書く前に「整理結果」タブ（'整理結果'!A:C）を読み、同じファイルIDの行が残っていれば（前回の途中失敗など）、
      その行の範囲を batch_clear_values で空にする。
      そのうえで整理結果を「整理結果」タブに追加する。Google Sheets の append_values で、範囲 '整理結果'!A:C、
      valueInputOption は RAW、各行は [B列のファイルID, 行番号（1から連番）, その行のテキスト]。
      行が多いときは 200 行ずつに分けて追加してよい（行番号は通しで振る）。
   g. 全行を書き終えてから、処理ログのその行を更新する（update_values、valueInputOption は RAW）。
      - M列: 「追記待ち」
      - S列: 書いた議事録の見出し（フォーマットの最初の見出し行から「#」と空白を除いた部分）
      - Y列: 手順 b2 で控えたセクションの見出し。対応するセクションが無ければ空にする
      - U列: 私（寺尾）に確認してほしい点があれば「です・ます調」で短く書く
        （例: 会議名をカレンダーから推定しました／区間3の終わりが欠けています）。無ければ空にする。
      M列・S列・U列・Y列以外は書き換えない。
4. 途中で失敗した場合（文字起こし文書が読めない等）は、M列は「整理待ち」のままにし、U列に理由を書いて次の行へ進む。
   （次回は手順 f で途中までの行を消してから書き直す）
```

## 動かし方のメモ

- 1回で最大2件にしているのは、2時間の会議の文字起こしは長く、1回の作業量が大きくなるためです。
- 整理結果を書き直したいときは、「整理結果」タブからそのファイルの行を消し、処理ログの M列を「整理待ち」に戻します
  （文字起こしは保持日数のあいだ残っています）。
