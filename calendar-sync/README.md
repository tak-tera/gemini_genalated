# カレンダー半同期（メイン ⇄ 組織カレンダー）設計案

メインカレンダー（terao.takeshi@t-consulting.biz）と、所属組織のカレンダー（まず東北大学 TU）の間で、
「中身は渡さず予定の枠だけ伝える」半同期を行う仕組みの検討メモです。

## 1. 現状の確認（2026-10〜11 の実データから）

| 観察したこと | 設計への影響 |
|---|---|
| メインのアカウントから TU カレンダー（takeshi.terao.c4@tohoku.ac.jp）に **書き込み権限あり** | スクリプトはメイン側アカウントだけで動かせる（TU 側に Apps Script を置かなくてよい） |
| TU の予定の多くは `calendar-sync2@tuadm.mail.tohoku.ac.jp` が作成し、タイトル先頭に `Sync: ` が付く（Garoon からの同期） | タイトル整形で `Sync: ` を外す。Garoon 側の同期とは衝突させない |
| TU のタイトルには `ハイブリッド:`、`_コワーキングスペース(情報部)`、`（ミラー）` などの管理情報が混ざる | 整形ルールを表で持つ |
| メインには手作業で `TU データ戦略室定例会` `TU AXIES企画打ち合わせ` などを登録済み。色は **colorId 1（ラベンダー）** | 先頭 `TU ` ＋ colorId 1 が「東北大学（TU）」カテゴリーの実体。初回は既存の手入力分を二重登録しないよう突き合わせる |
| TU 側には手作業の不在ブロック `（打ち合わせ）` `（研修講演）` `（研修GW）` `（不在）` が **不在（OUT_OF_OFFICE）** で入っている | 自動ブロックも同じ形式。手作業分は触らない |
| 手作業ブロックは 9:00〜18:00 に収まり、近い予定はまとめて1つのブロックにしている（例: 10/28 13:30〜18:00） | 勤務時間でのはみ出しカットと、隣り合うブロックの結合を入れる |
| オンラインの打ち合わせは前後の余白なしでブロックしている例がある（10/21、11/2） | 「オンラインは余白なし」を選べるようにする（要確認） |
| メインには MWU・JUAM・Jagu'e'r など他組織の予定、移動（近鉄・ひのとり）、ホテル、終日予定が混在 | 対象外ルール（移動・宿泊・終日・夜間）が必要。MWU なども将来の組織候補 |

## 2. 全体構成

```
                    ┌──────────── メインカレンダー（ハブ） ────────────┐
                    │  自分の予定（MWU, JUAM, 研修 …）                 │
                    │  TU 由来の予定「TU ○○」（色: ラベンダー）        │
                    └───────▲──────────────────────┬────────────────────┘
       ② 組織の予定を写す   │                      │ ① 枠だけを不在で入れる
       （タイトル整形・色）  │                      ▼
                    ┌───────┴─────────┐   ┌────────────────────┐
                    │ TU カレンダー    │   │ TU カレンダー        │
                    │ 「Sync: …」等    │   │ 「（打ち合わせ）」等 │
                    └─────────────────┘   └────────────────────┘
         （将来）MWU カレンダー など、同じ形で何組織でも足せる
```

- **メインをハブにする**: 組織 A の予定はメインに写す（②）。メインの予定は、それが生まれた組織以外のすべての組織に不在ブロックとして伝える（①）。
  組織が増えても「TU の会議 → MWU に不在」が自然に成り立つ。
- **実行場所**: メイン側アカウントの Apps Script（既存の gmail-quire-sync と同じ流儀）。高度なサービス「Calendar API」を使う。
- **実行タイミング**: 10分ごとの時間主導トリガー。Calendar API の `syncToken` で「前回から変わった予定だけ」を取得する。
  対象期間は今日〜90日先。
- **設定と記録**: スプレッドシート（組織設定・分類ルール・タイトル整形・同期ログ）。コードを触らずに組織や言葉を追加できる。

## 3. ① メイン → 組織：不在ブロック

### 3.1 対象にする予定・しない予定

対象外（上から順に判定）:
1. スクリプト自身が作った予定（拡張プロパティ `syncOrigin` あり）＝組織から写した「TU ○○」
2. 先頭が組織の接頭辞（`TU ` など）の手入力予定 … その組織の予定なので、その組織には返さない（他組織には返す）
3. 終日予定、複数日にまたがる予定（ホテルなど）
4. 移動（`→` `~` を含む、`近鉄` `新幹線` `ひのとり` `のぞみ` など）、宿泊（`ホテル` `イン` `HOTEL`）
5. 自分が「欠席」と回答した予定、空き時間（透過）の予定
6. 組織の勤務時間（例 9:00〜18:00、平日）と1分も重ならない予定（夜の Jagu'e'r 定例など）

### 3.2 分類と枠の取り方

| 分類 | 判定キーワード（例） | TU に入るタイトル | ブロックする時間 |
|---|---|---|---|
| 打ち合わせ | 打ち合わせ, 打合せ, 定例, 会議, 委員会, MT, MTG, ミーティング, ディスカッション, 来訪, 面談 | （打ち合わせ） | 開始1時間前〜終了1時間後（オンラインは余白なし…要確認） |
| 研修講演 | 研修, 講演, 登壇, セミナー, ゼミナール, ワークショップ, 講義, 研究会, 記念事業 | （研修講演） | 「開始2時間前」から後ろへ見て、最初に空いている時刻〜終了（＋余白は要確認） |
| 判断できない | 上のどれにも当たらない | （不在） | 予定どおりの時間（余白なし）。同期ログに「要確認」と残す |

- **判定の順番**: 打ち合わせ系を先に見る。`研修打ち合わせ` `SD研修打ち合わせ` は「打ち合わせ」になる。
- **研修講演の「空いているところから」**: 開始2時間前の時刻に TU 側で別の予定（実際の会議）が入っていれば、その予定の終了時刻から開始する。
  開始時刻まで空きがなければ予定の開始時刻から。
- **勤務時間でカット**: ブロックは 9:00〜18:00 の範囲に切り詰める。
- **結合**: 同じ日のブロック同士が重なる、または30分以内の隙間なら1つにまとめる。タイトルは強い方（研修講演 ＞ 打ち合わせ ＞ 不在）。
  例: 10/29 の MWU 13:00〜15:00 と 15:30〜17:30 → 12:00〜18:00 の（打ち合わせ）1つ。
- **予定の形式**: 既存の手作業ブロックと同じ「不在（outOfOffice）」。ただし **自動辞退はしない**（`autoDeclineMode: declineNone`）。
  余白の時間に TU の会議が入っていても勝手に辞退されないようにするため。
- **中身は渡さない**: タイトルは固定文言のみ。説明・場所・参加者はコピーしない。

### 3.3 変更・削除への追従

- メインの予定の時間が変わった／消えた → 対応するブロックを作り直す／消す。
- 結合ブロックは「その日のブロックを毎回計算し直して差分だけ反映」する方式にする（1予定＝1ブロックの対応を持たない）。
  その日のブロック一式には拡張プロパティ `syncOrigin=main`, `syncDay=2026-10-29` を付け、スクリプトが作ったものだけを消し替える。手作業のブロックには触れない。

## 4. ② 組織 → メイン：予定を写す

### 4.1 対象にする予定・しない予定

対象外:
1. 不在・作業時間・勤務場所の予定（自分のブロック。手作業の「（…）」も含む）
2. スクリプトが作ったもの（`syncOrigin` あり）、メイン側アカウントが作ったもの
3. 自分が「欠席」と回答したもの
4. 同じ時間に、同じ組織の接頭辞付きでメインに既にある手入力予定 → **新しく作らず、その予定と紐付ける**（初回移行用）

要確認: 終日の通知系（`全学一斉安否情報登録訓練` など）、任意参加（optional）・未回答の招待をどう扱うか。

### 4.2 タイトルの整形（TU の例）

整形ルールは表で持ち、上から順に適用する。

| 種類 | パターン | 結果 |
|---|---|---|
| 削除 | 先頭の `Sync:` | |
| 削除 | `ハイブリッド:` `オンライン:` `対面:` | |
| 削除 | `_` 以降の会場名（`_コワーキングスペース(情報部)`） | 場所欄へ回す |
| 削除 | `（ミラー）` | 説明欄に「ミラー参加」と残す |
| 置換 | `打合` → `打ち合わせ`、全角スペース → なし | |
| 短縮 | 40文字を超える場合は最初の `（` より前だけ | |
| 付与 | 先頭に `TU ` | |

例:
- `Sync: ハイブリッド:データ戦略室定例会_コワーキングスペース(情報部)` → `TU データ戦略室定例会`（手入力と一致）
- `Sync: AXIES　企画打合` → `TU AXIES企画打ち合わせ`（手入力と一致）
- `Sync: EM打ち合わせ（画面確認：キャリアパス関連…）` → `TU EM打ち合わせ`
- `Sync: 経営企画会議（ミラー）` → `TU 経営企画会議`

「推測」が必要な残り（長い・あいまいなタイトル）は、オプションで生成 AI（Gemini API など）に
「15文字程度の予定名に要約。会場・形式・管理用の語は除く」と頼む。ルールで十分なら使わない。

### 4.3 写す内容

| 項目 | 内容 |
|---|---|
| タイトル | 整形後（`TU ○○`） |
| 時間 | 同じ |
| 色（カテゴリー） | 組織設定の colorId（TU は 1＝ラベンダー。画面上のラベル名「東北大学（TU）」は API からは指定できないので、色番号で合わせる） |
| 場所 | 会場名（`location` または `_` 以降から取った部屋名） |
| 説明 | TU 側予定へのリンクと Meet/Teams の URL のみ。本文（資料の場所・参加者・取扱注意の内容）はコピーしない |
| 公開設定 | 非公開（private） |
| 予定あり／空き | 予定あり |

TU 側で時間が変わればメインも直し、取り消されればメインからも消す（スクリプトが作ったもの／紐付けたものだけ）。

## 5. ループ（行ったり来たり）の防止

- スクリプトが作る予定にはすべて拡張プロパティ（非公開）を付ける: `syncOrigin`（main / TU / …）、`syncSourceId`（元の予定 ID）、`syncOrg`。
- ①は `syncOrigin` 付きの予定を元にしたブロックを、その `syncOrigin` の組織には作らない。
- ②は不在予定と `syncOrigin` 付きの予定を写さない。
- これで「TU の会議 → メインに TU ○○ → TU に（打ち合わせ）」という跳ね返りが起きない。

## 6. スプレッドシートの構成

| タブ | 主な列 |
|---|---|
| 組織設定 | 有効, 組織コード（TU）, 表示名（東北大学（TU））, カレンダー ID, メインでの接頭辞（`TU `）, colorId, 勤務時間（9:00-18:00）, 勤務曜日, ブロック形式（不在／予定あり）, 結合する隙間（30分） |
| 分類ルール | 有効, 順番, 組織コード（空欄＝全組織）, キーワード／正規表現, 分類（打ち合わせ／研修講演／対象外）, 前の余白, 後の余白, 余白の取り方（固定／空きから）, オンライン時の余白 |
| タイトル整形 | 有効, 順番, 組織コード, パターン（正規表現）, 置換後, 行き先（削除／場所へ／説明へ） |
| 同期ログ | 日時, 方向, 組織, 元の予定 ID, 元タイトル, 作った予定 ID, 結果タイトル, 分類, 状態（作成／更新／削除／要確認／エラー） |

組織を増やすときは「組織設定」に1行、必要なら「タイトル整形」に数行足すだけにする。

## 7. 進め方（案）

1. **お試し（書き込みなし）**: 判定結果を同期ログに書くだけ。2週間分を見て分類ルールと整形ルールを調整。
2. **② 組織 → メイン** を有効化（既存の手入力と紐付け → 新規だけ作成）。
3. **① メイン → 組織** を有効化。最初の数日は TU 側で結果を目視確認。
4. 2つ目の組織（例: MWU）を組織設定に追加。

## 8. 決めてほしいこと

1. 打ち合わせの「前後1時間」は **オンラインでも取りますか**（手作業ではオンラインは余白なしの例あり）。
2. 研修講演は **終了後にも余白** を取りますか（例: 1時間）。
3. TU の勤務時間は **9:00〜18:00・平日** でよいですか。範囲外の予定はブロック不要でよいですか。
4. 移動（新幹線など）は対象外でよいですか。それとも「（移動）」としてブロックしますか。
5. TU ブロックは今と同じ **不在** 形式でよいですか（Garoon 側にどう見えるかは要確認）。
6. メインの色: TU は **ラベンダー（colorId 1）** で合っていますか。
7. TU の任意参加・未回答の招待、終日の通知（訓練など）はメインに写しますか。
8. タイトル推測はルールのみで始め、足りなければ生成 AI を足す方針でよいですか。

## 9. 注意点・確認事項

- **不在予定を他人のカレンダーに API で作れるか**: 不在（outOfOffice）は本来そのユーザー本人の操作が前提。メイン側アカウントからの API 作成が拒否された場合は、
  「予定あり・非公開の通常予定」で代用する（見え方はほぼ同じ、自動辞退はなし）。最初に1件だけ試して確かめる。
- **Garoon 同期への影響**: TU に作ったブロックが Garoon 側に反映されるかは東北大学の同期設定しだい。反映されるなら Garoon 上でも不在として見える（望ましい方向）。
- **東北大学の規程**: 予定の中身は渡さず「枠」だけ渡す設計にしてある。メインへ写す際も本文はコピーしない。
- **Apps Script の上限**: 10分ごと・90日先までなら一般的な利用量の範囲内。
