# カレンダー半同期（メイン ⇄ 組織カレンダー）

メインカレンダー（terao.takeshi@t-consulting.biz）と、所属組織のカレンダー（まず東北大学 TU）の間で、
「中身は渡さず予定の枠だけ伝える」半同期を行う仕組みの検討メモです。

## 1. 現状の確認（2026-10〜11 の実データから）

| 観察したこと | 設計への影響 |
|---|---|
| メインのアカウントから TU カレンダー（takeshi.terao.c4@tohoku.ac.jp）に **書き込み権限あり** | スクリプトはメイン側アカウントだけで動かせる（TU 側に Apps Script を置かなくてよい） |
| TU の予定の多くは `calendar-sync2@tuadm.mail.tohoku.ac.jp` が作成し、タイトル先頭に `Sync: ` が付く（Garoon からの同期） | タイトル整形で `Sync: ` を外す。Garoon 側の同期とは衝突させない |
| TU のタイトルには `ハイブリッド:`、`_コワーキングスペース(情報部)`、`（ミラー）` などの管理情報が混ざる | 整形ルールを表で持つ |
| メインには手作業で `TU データ戦略室定例会` `TU AXIES企画打ち合わせ` などを登録済み。色は **colorId 1（ラベンダー）** | 先頭 `TU ` ＋ colorId 1 が「東北大学（TU）」カテゴリーの実体。初回は既存の手入力分を二重登録しないよう突き合わせる |
| TU 側には手作業の不在ブロック `（打ち合わせ）` `（研修講演）` `（研修GW）` `（不在）` が **不在（OUT_OF_OFFICE）** で入っている | 自動ブロックも同じ形式。手作業分は触らない |
| 手作業ブロックは 9:00〜18:00 に収まり、近い予定はまとめて1つのブロックにしている（例: 10/28 13:30〜18:00） | 勤務時間でのはみ出しカットと、隣り合うブロックの結合を入れる |
| メインには MWU・JUAM・Jagu'e'r など他組織の予定、移動（近鉄・ひのとり）、ホテル、終日予定が混在 | 対象外ルール（移動・宿泊・終日・夜間）が必要。MWU なども将来の組織候補 |

## 2. 全体構成

```
                    ┌──────────── メインカレンダー（ハブ） ────────────┐
                    │  自分の予定（MWU, JUAM, 研修 …）                 │
                    │  TU 由来の予定「TU ○○」（色: ラベンダー）        │
                    └───────▲──────────────────────┬────────────────────┘
       ② 組織の予定を写す   │                      │ ① 枠だけを不在で入れる
       （タイトル整形・色）  │                      ▼
                    ┌───────┴─────────┐   ┌────────────────────┐
                    │ TU カレンダー    │   │ TU カレンダー        │
                    │ 「Sync: …」等    │   │ 「（打ち合わせ）」等 │
                    └─────────────────┘   └────────────────────┘
         （将来）MWU カレンダー など、同じ形で何組織でも足せる
```

- **メインをハブにする**: 組織 A の予定はメインに写す（②）。メインの予定は、それが生まれた組織以外のすべての組織に不在ブロックとして伝える（①）。
  組織が増えても「TU の会議 → MWU に不在」が自然に成り立つ。
- **実行場所**: メイン側アカウントの Apps Script（既存の gmail-quire-sync と同じ流儀）。高度なサービス「Calendar API」を使う。
- **実行タイミング**: 10分ごとの時間主導トリガー。毎回、今日〜90日先の「あるべき姿」を計算し、スクリプトが作った予定との差分だけを書き込む。
- **設定と記録**: スプレッドシート（組織設定・分類ルール・タイトル整形・同期ログ）。コードを触らずに組織や言葉を追加できる。

- **フォルダ構成**: `apps-script/`（コード）、`docs/setup.md`（設定手順）

## 3. ① メイン → 組織：不在ブロック

### 3.1 対象にする予定・しない予定

対象外:
1. その組織の予定（先頭が接頭辞 `TU `、色がラベンダー、またはその組織から写した予定）。`（TU 打ち合わせ…）` のようにカッコ始まりでも判定する
2. 移動（`近鉄` `新幹線` `ひのとり` `特急` `→` など）と宿泊（`ホテル` `HOTEL` `フレッサイン` など）… 移動中もオンライン会議に出ることがあるため空けておく
3. 欠席と回答した予定
4. 終日・12時間以上の予定のうち、分類キーワードに当たらないもの（`東北大（大経大候補）` などのメモ的な予定）

メイン側の「空き時間」の設定は見ない（終日予定は既定で空き時間になるため）。

### 3.2 分類と枠の取り方（分類ルールタブ・上から順に判定）

| 分類 | キーワード（初期値） | TU のタイトル | 前の余白 | 後の余白 |
|---|---|---|---|---|
| 打ち合わせ | 打ち合わせ, 打合せ, 定例, 会議, 委員会, ミーティング, MTG, MT, ディスカッション, 来訪, 面談, 相談, ヒアリング | （打ち合わせ） | 60分 | 60分 |
| 研修講演 | 研修, 講演, 登壇, 講義, 授業, セミナー, ゼミナール, ワークショップ, 研究会, シンポジウム, フォーラム, 記念事業 | （研修講演） | 120分 | 60分 |
| 不明 | どれにも当たらない | （不在） | 0 | 0 |

- オンラインでも余白は取る。ただし **TU 側の実際の予定と重なる分は余白を削る**（＝空いているところからブロック）。
  研修講演の「開始2時間前の空いているところから」も同じ仕組み。
- 打ち合わせ系を先に判定するので `研修打ち合わせ` は打ち合わせになる。
- 終日・長時間の予定でキーワードに当たるもの（`JAST GAKUENユーザー研修会＠北海道` など）は、その日の 8:00〜18:00 をブロック（API では不在予定を終日にできないため時間指定で作る）。
- ブロックは **平日 8:00〜18:00** に切り詰める（組織タブで変更可）。範囲外だけの予定はブロックしない。
- 同じ日のブロックは重なるか30分以内の隙間なら1つにまとめる。タイトルは 研修講演 ＞ 打ち合わせ ＞ 不在。
- 手作業の不在ブロックで完全に覆われている時間には作らない。手作業のブロックには触れない。
- 形式は不在（outOfOffice）、**自動辞退なし**。不在で作れない場合は自動で通常の予定で代用する。
- 中身は渡さない（タイトルは固定文言のみ）。

## 4. ② 組織 → メイン：予定を写す

### 4.1 対象

写さない:
- 不在予定（手作業の「（…）」を含む）、このスクリプトが作った予定
- 欠席・**未回答**の招待
- タイトルに `【スキップ】` `【中止】` `【休会】` `【キャンセル】` を含むもの（タイトル整形タブで「写さない」に指定）

終日の予定（訓練など）は写す。

### 4.2 タイトル整形（タイトル整形タブ・上から順に適用）

| パターン | 処理 |
|---|---|
| `Sync:` | 削除 |
| `ハイブリッド:` `オンライン:` `対面:` `Web:` | 削除 |
| 先頭の `12:00_` のような時刻 | 説明へ |
| `_` 以降の会場名 | 場所へ |
| `（ミラー）` | 説明へ |
| `打合` `打合せ` | `打ち合わせ` に統一 |
| 全角スペース | 削除 |
| 30文字超 | 最初のカッコより前だけ |
| 先頭 | `TU ` を付ける |

実データでの結果:
- `Sync: ハイブリッド:データ戦略室定例会_コワーキングスペース(情報部)` → `TU データ戦略室定例会`
- `Sync: EM打ち合わせ（画面確認：キャリアパス関連…）` → `TU EM打ち合わせ`
- `Sync: 経営企画会議（ミラー）` → `TU 経営企画会議`
- `Sync: 12:00_全学一斉安否情報登録訓練` → `TU 全学一斉安否情報登録訓練`（終日）
- `Sync: 対面:大阪経済大学さま来訪` → `TU 大阪経済大学さま来訪`

### 4.3 写す内容

- 色: 組織タブの色番号（TU は 1＝ラベンダー）。カテゴリー＝色＋接頭辞の対応は組織タブで持つ
- 場所、会議 URL（Meet/Teams/Zoom）、元の予定へのリンク。本文（資料・参加者・取扱注意の内容）はコピーしない
- 非公開・予定あり
- **初回移行**: 同じ時間に `TU ○○` の手入力予定があれば、新しく作らずに紐付ける（タイトルはそのまま、時間だけ追従）。
  元の予定が消えても手入力の予定は削除せず、同期ログに「要確認」と残す

## 5. ループの防止

スクリプトが作る予定には非公開の目印（`calSync` / `calSyncOrg` / `calSyncSrc`）を付ける。
写した予定はその組織へのブロック対象にならず、ブロックは写す対象にならない。

## 6. スプレッドシート

| タブ | 内容 |
|---|---|
| 設定 | 書き込みモード（お試し／本番）、対象期間、結合する隙間、タイトルの最大文字数 |
| 組織 | 組織コード、表示名、カレンダー ID、接頭辞、色番号、ブロック時間・曜日、ブロック形式、各方向の有効／無効 |
| 分類ルール | キーワード → 分類・TU のタイトル・前後の余白・結合時の優先度 |
| タイトル整形 | 正規表現 → 置き換え・行き先（削除／場所へ／説明へ／写さない） |
| 同期ログ | 本番で行った操作 |
| プレビュー | お試し実行の判定結果と、本番にした場合の操作 |

## 7. 実データでの確認（10/20〜11/20、手元のテスト）

- TU → メイン: 作成 6 件、手入力の予定と紐付け 6 件。`【スキップ】` の定例会と未回答の KPMG 招待は写さない
- メイン → TU: 13 件のブロック。例: 10/29 の MWU 2コマ → 12:00〜18:00 の1件、11/13 の都立大集合＋研修 → 12:00〜18:00（研修講演）
- 2回目の実行は書き込み0件。TU 側の時間変更・取り消し、メイン側の削除にも追従

## 9. 注意点

- 不在予定を他のアカウントのカレンダーに API で作れるかは `testOutOfOffice` で確認する。作れなければ「予定あり」形式にする
- TU に作ったブロックが Garoon に反映されるかは東北大学の同期設定しだい
- 夜の予定でも、前の余白が 18:00 前にかかればブロックされる（例: 18:00 開始の会議 → 17:00〜18:00）。不要なら分類ルールで調整
